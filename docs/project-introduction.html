01 / 项目定位

解决的不是“把文档变成文本”，而是把标准变成可执行需求

技术标准的难点在于信息分散、结构混合、引用复杂和责任边界模糊。项目把解析、语义判断、证据核对和专家裁决组织为同一条可审计流水线。

01

从异构文档恢复结构

统一处理章节、段落、表格、对象字段与来源坐标，保留原文块和表格单元格证据，而不是只输出一段不可追溯的摘要。

02

从描述中拆出可评审需求

将一段中的行为、条件、数值、例外和验证要求拆成审查单元，同时保留跨条款引用、术语上下文与原文锚点。

03

从需求条目走到研发交付

通过专家裁决、功能重组、软硬件归属、模板成文与澄清闭环，把中间原子结果继续装配成研发团队真正使用的规格和工作簿。

02 / 双轨方法

根据文档形态选择主轨，而不是让一种抽取逻辑包打天下

对象表密集的 DLMS profile 与行为散文型招标/标准，信息组织方式不同。项目保留 A、B 两条主轨，并在交付层汇合。

Track A · deterministic structure

DLMS / COSEM 对象表轨

适用文档
对象表、OBIS、接口类、属性与访问权限密集的 profile 文档。
主链
规则原子化 → 可选 LLM 审查 → P1-P5 实现规格装配。
核心优势
结构字段通过确定性 join 生成，编码与访问位不交给模型猜测。
主交付物
dlms_cosem_spec.*、对象模型、访问矩阵和工程规格。
Track B · semantic behavior

行为散文与招标文档轨

适用文档
需求隐藏在自然语言、测试描述和跨章节上下文中的标准或招标文件。
主链
AI 抽取 → 专家批注 → 功能重组 → 软件需求分析 → 模板成文。
核心优势
章节级语义抽取配合自检、漂移护栏、遗漏标记和定点补抽。
主交付物
software_requirements.xlsx 与公司模板格式需求列表。

03 / 核心能力

围绕“清晰展示解析结果”构建的完整工作面

系统不是单次转换脚本。解析结果能够回到原文、进入专家裁决、驱动重建，并继续流向研发交付物。

Parse

多格式结构解析

支持 DOCX、XLSX 与文字层 PDF，输出统一的 blocks、table items、章节和来源定位。

Extract

规则与 AI 双引擎

结构数据走确定性抽取；行为散文走章节级 LLM、自检和二遍语义复核，并保留降级路径。

Review

工具化证据审查

模型可调用五个只读工具查询知识库、Blue Book class、原文块和覆盖一致性，调用轮次与预算有硬上限。

Annotate

原文联动批注

点击 PDF 或文本原文即可查看对应解析；证据区、分析范围、重复回声和失败章节均可定位。

Synthesize

功能重组与归属分析

过滤被拒条目，投影专家模块/归属改判，保守合并相容需求并保留冲突与来源诊断。

Close loop

澄清与遗漏闭环

客户答复和内部核对进入审计状态；确认遗漏可定点补抽，并使相关下游阶段按指纹失效重跑。

04 / 质量护栏

确定性骨架 + 护栏化 LLM + 专家终审

项目的核心纪律是“宁漏勿错”。模型可以帮助理解和叙述，但不能静默改变结构事实，也不能把失败伪装成成功。

D

结构字段确定性

OBIS、class_id、访问权限、ID、模块和归属等关键字段由解析、规则或专家裁决控制。

G

数字与编码漂移防护

无来源编码硬拒；直接影响研发执行的无据数字拒绝或转“待澄清”，普通叙述风险随条目标记。

P

来源和路由不伪造

产物记录 producer、版本、时间和证据；route_requested 与实际 route 分开，stub 不冒充 LLM。

C

缓存血统可失效

输入内容、提示词、护栏、工具、模型、风险策略和 domain pack 进入指纹，行为升级不会被旧缓存绕过。

L

共享状态并发安全

审查、裁决、manifest 与追加缓存使用跨进程锁、fsync、原子替换及 Windows 文件占用重试。

E

失败边界显式

端点不可用、工具循环超限、证据变化或校验失败都会留下可见状态，历史裁决不会静默沿用。

05 / 系统架构

桌面界面、本地任务桥与 Python 核心解耦

正式产品采用 Vue3 + Electron；任务通过本地桥接调用 Python 流水线，审查工作台使用本地 API。旧 PySide6 界面保留但已冻结。

交互层
  • Vue3 工作台运行概览、文档批注、需求与交付物入口
  • Electron 主进程目录选择、密钥安全存储、后端进程管理
  • 离线批注 HTML可分享的原文与解析结果审查页面
→
本地核心
  • desktop_tasks / api_server阶段编排、进度事件、manifest 与裁决 API
  • parsers / atomize / ai_extract结构解析、规则候选与语义抽取
  • llm_pipeline / review_tools有界工具审查、证据检索和政策合并
  • requirements_analysis / assemble_spec功能重组、软硬件分析与实现规格装配
→
知识与交付
  • requirement_kbObsidian 编译知识库与确定性检索
  • domain_packs / Blue Book领域模式、风险政策与接口类证据
  • JSONL / XLSX / HTML / MD机器接口、研发工作簿、批注和人读规格

07 / 技术与运行

本地优先部署，LLM 按需启用

默认 stub 路由不调用外部 API。需要语义抽取或叙述富化时，可接入 OpenAI 兼容端点；密钥仅通过环境变量或 Electron 安全存储进入会话。

Python 3.11+解析、抽取、审查、装配与本地 API
Vue 3 + TypeScript正式桌面工作台与审查交互
Electron + ViteWindows portable 应用与前端构建
PyInstaller冻结单文件 Python 后端
PowerShell · 典型命令
# 完整解析与审查
ratomizer run ".\standard.pdf" --out ".\out\run-001" --export md,csv

# 从专家裁决后的结果生成研发需求
python -m desktop_tasks functional-synthesis --out ".\out\run-001"
ratomizer analyze --out ".\out\run-001" --llm-route stub

# 启动 Vue3 + Electron 桌面端
cd .\ui
npm run desktop:dev
当前版本边界
  • 支持 DOCX、XLSX 和有可提取文字层的 PDF；旧版 XLS 需先另存为 XLSX。
  • 扫描件 PDF 的 OCR 尚未纳入当前版本，需先转为可解析文档。
  • LLM 是可选能力；无密钥或端点不可用时会诚实降级，不会伪造模型结果。
  • 正式产品界面是 Vue3 + Electron；仓库中的 PySide6 GUI 已冻结。
  • Windows portable 当前未签名，分发时可能触发 SmartScreen 提示。
