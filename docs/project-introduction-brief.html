Local-first · 需求工程流水线

Requirement Atomizer

把技术标准（DOCX / XLSX / 文字层 PDF）原子化为可审查、可追溯、可交付的研发需求。

确定性解析建立事实骨架，护栏化 LLM 只做判断与叙述，专家裁决作为最终质量关口。全部本地运行，默认不调用任何外部 API。

  • 3 类输入DOCX / XLSX / 文字层 PDF
  • 2 条主轨对象表轨 / 行为散文轨
  • 5 个审查工具知识库 / 蓝皮书 / 原文 / 覆盖
  • 1664+ 回归后端 unittest + 前端契约测试

01双轨方法

适用文档主链主交付物
A 轨 · 对象表 OBIS / 接口类 / 访问权限密集的 DLMS profile 文档 规则原子化 → 可选 LLM 审查 → 规格装配 dlms_cosem_spec.* 实现规格
B 轨 · 散文 需求藏在自然语言里的标准 / 招标文件 AI 抽取 → 专家批注 → 功能重组 → 需求分析 → 模板成文 software_requirements.xlsx 及公司模板需求列表

02六步链路

  1. 解析文档块、表格、章节层级与来源坐标（blocks / table_items）。
  2. 抽取结构数据走确定性规则；行为散文走章节级 LLM + 自检与漂移护栏。
  3. 取证模型可调用五个只读工具查知识库、蓝皮书、原文与覆盖，轮次与预算有硬上限。
  4. 裁决专家在原文联动批注页接受 / 拒绝 / 改判模块与软硬件归属。
  5. 分析保守合并相容需求，生成研发行为、条件、约束与验收关注点。
  6. 交付实现规格、研发工作簿、批注页面与客户澄清清单。

03质量纪律：宁漏勿错

  • 结构字段确定性OBIS、class_id、访问权限、ID 由解析 / 规则 / 专家控制，不交给模型猜。
  • 数字编码漂移防护无来源编码硬拒；无据数字拒绝或转「待澄清」，标记随条目走到交付物。
  • 来源不伪造route_requested 与实际 route 分开记账，stub 降级绝不冒充 LLM 结果。
  • 缓存血统可失效输入、提示词、护栏、工具、模型版本全进指纹，行为升级不被旧缓存绕过。

05技术与运行

Python 3.11+ 核心 · Vue 3 + TypeScript 工作台 · Electron + Vite 桌面端 · PyInstaller 单文件后端。正式界面是 Vue3 + Electron，旧 PySide6 GUI 已冻结。

# 完整解析与审查
ratomizer run ".\standard.docx" --out ".\out\run-001" --export md,csv

# 专家裁决后生成研发需求
python -m desktop_tasks functional-synthesis --out ".\out\run-001"
ratomizer analyze --out ".\out\run-001" --llm-route stub

# 启动桌面端
cd ui && npm run desktop:dev
  • 旧版 XLS 需先另存为 XLSX；扫描件 PDF 的 OCR 尚未支持，需先转为可解析文档。
  • LLM 为可选能力：无密钥或端点不可用时诚实降级，绝不伪造模型结果。
  • Windows portable 包当前未签名，分发时可能触发 SmartScreen 提示。
