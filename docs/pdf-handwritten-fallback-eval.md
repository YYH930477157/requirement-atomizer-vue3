# PDF 手写解析器退役/保留评估（A8①）

> 状态：结构审查级评估（structural review）。
> 当前无真实 A/B 运行数据，因此本评估基于代码结构、已知失效模式与维护成本，
> 而非端到端指标对比。获得真实 A/B 数据后应更新结论。

## 1. 评估对象

`parsers/pdf_parser.py` 手写 pdfplumber 解析器，约 82 KB，承担：

- 文字层采样与扫描件检测
- 页眉页脚噪声识别
- 词内空格碎词修复（`defragment_text_with_audit`）
- 无画线表格文本重建
- 画线表 bbox/合并格几何证据
- 清单段合并、续行合并、标题拆分

## 2. 退役前提

退役手写解析器需要替代方案在以下维度达到或超过当前实现：

| 维度 | 当前手写能力 | 替代方案需证明 |
|---|---|---|
| 文字层可用性门 | 前 5 页平均字符数 ≥100 | 同等级别 fail-fast |
| 碎词修复 | 82 KB 机翻 PDF 实测修复，可配置词典 | 同输入下引用锚定不劣化 |
| 无画线表格 | 多守卫链，ABNT 零新增伪表 | 不引入整页误并为表 |
| 几何证据 | cell bbox + merge range + 矛盾检测 | 等价或更精确 |
| 噪声清除 | 重复页眉页脚、版权水印 | 不丢失正文 |

## 3. 当前结论：保留，直至 A/B 数据证伪

在没有真实 A/B 数据前，**不建议退役手写解析器**。原因：

1. **碎词与无画线表是真实痛点**：已在 UNI 12007、EN 16314、test6 等文档上验证，替代方案需逐案复跑。
2. **可观测性差**：现代 PDF 解析器输出结构化 table，但页眉页脚过滤、续行合并、标题拆分等行为不透明，需大量 golden 用例锁定。
3. **默认路径稳定**：`RATOMIZER_PDF_MODERN_PARSER=0` 时，当前路径是生产唯一路径；现代解析器开关已预留 A/B 入口。

## 4. 可渐进引入现代解析器的路径

- **阶段 1（当前）**：现代解析器仅处理 table structure（已落地 `pdf_modern_adapter` 适配层入口，默认 OFF）。
- **阶段 2**：对 table structure 做 A/B，统计 table cell 守恒、角色准确率、几何命中率。
- **阶段 3**：现代解析器处理 prose，与手写路径做整文档 A/B，对比覆盖率、引用锚定、噪声率。
- **阶段 4**：若 A/B 连续通过且维护成本更低，再讨论默认切换；切换时必须 bump `PDF_TEXT_REPAIR_VERSION` 等价行为版本并重建 golden。

## 5. 风险与观察指标

| 风险 | 观察指标 |
|---|---|
| 现代解析器误判无画线表格 | 伪表导致需求丢失/噪声需求增加 |
| 现代解析器不修复碎词 | source_quote 锚定失败率上升 |
| 现代解析器丢失几何矛盾信息 | table-cell claim 热区错位 |

## 6. 词典重分词器（A8②）的定位

`parsers/pdf_resegment.py` 作为碎词修复的补充/替换实验入口：

- 默认关闭（`RATOMIZER_PDF_RESEG`）。
- 可配置 YAML/TXT 词表（`RATOMIZER_PDF_RESEG_WORDLIST`）。
- 开启后可用于对比默认 `defragment_text_with_audit` 的召回与误修率，为现代解析器碎词处理提供基准。

## 7. 建议

- **保留手写解析器为生产默认**。
- **继续用 `RATOMIZER_PDF_MODERN_PARSER` 做 table-only 现代解析实验**。
- **获得真实 A/B 数据后更新本文档**，将"结构审查级"升级为"数据驱动级"，再决定是否退役。
